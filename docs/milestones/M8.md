# M8 — Release candidates to v1.0.0

M8 hardens the pre-1.0 release path without weakening local-first behavior, native model
transport, or explicit execution approval. The repository-controlled implementation is ready
for a protected release rehearsal.

## Verified in the repository

- Protocol v1 and schema 1 are frozen and checked against the MCP wire fixture.
- Coordinated 0.2.2 metadata, migration guidance, and release notes exist.
- RC artifacts use deterministic aggregate and per-file SHA-256 checksums.
- RC verification requires one valid CycloneDX SBOM and checks every checksum sidecar.
- Protected CI emits GitHub artifact attestations: a separate CycloneDX SBOM attestation and
  default SLSA build provenance over the complete release directory.
- Ed25519 compatibility-manifest signing and independent verification tools are tested without
  storing keys in the repository.
- Windows, macOS, and Ubuntu CI plus Security passed for the daemon readiness fix at `31a2e21`.
- The macOS startup race was fixed by completing a read-only health handshake before reporting
  daemon startup success.

## Maintainer gates still required

- Confirm npm, crate, VS Code publisher, repository, support, rollback, and signing identities.
- Obtain an independent clean-room reviewer sign-off.
- Publish a release candidate to a non-default npm channel and complete clean-machine tests.
- Run the documented benchmark on reference hardware and a 24-hour daemon soak.
- Publish the signed compatibility manifest only after every referenced artifact is public and
  independently verified.
- Approve the stable tag and publish surfaces in dependency order.
