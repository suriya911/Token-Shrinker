# M1.1: Caveman output policy

Status: Complete  
Completed: 2026-08-07

## Delivered

- seven serializable output modes with `full` as the default;
- exact request, session, tool, agent, and global precedence;
- English and Wenyan clarity escalation for security warnings, irreversible actions, ordered recovery, and meaning-sensitive text;
- mandatory formatter bypass for machine-readable payloads, raw evidence, source code, third-party messages, and internal text;
- non-configurable preservation classes for code, commands, paths, errors, numbers and units, citations, warnings, uncertainty, and negation;
- nine public JSON fixtures covering precedence, clarity, and bypass behavior.

## Acceptance commands

```text
pnpm check
git diff --check
```

The output-policy suite includes fixture-driven contract testing plus exhaustive tests for protected span classes and non-human payload bypass.

## Scope boundary

M1.1 resolves whether and how a normalized human-facing payload may be formatted. It does not rewrite text itself. Deterministic extractive compression and language-specific rendering are separate implementation work and must consume this policy decision.

## Known risks

- Agent and tool override keys are not yet validated against a capability registry.
- Automatic clarity selects a safer profile but cannot evaluate semantic fidelity until a formatter exists.
- Protected-span detection and byte-range preservation are not implemented in this milestone.
- Wenyan modes preserve their configured language family during clarity escalation; localization review remains future work.
