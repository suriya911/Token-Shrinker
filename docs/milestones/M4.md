## Security boundaries

- MCP execution remains explicitly annotated as destructive and uses the M3 pre-spawn argument-array policy; the server does not interpret shell strings.
- Stdio MCP uses process ownership and no HTTP authorization surface; reusable clients use the authenticated per-user daemon transport.
- MCP and CLI results always preserve structured warnings, request IDs, protocol versions, citations, and machine JSON regardless of Caveman settings.
- The npm launcher has no install script, downloader, runtime network fallback, or duplicate JavaScript CLI implementation.
- Update checks authenticate the canonical unsigned manifest with a trusted Ed25519 key before resolving any component or artifact.
- Update checks are read-only: owner actions are reported but never executed.

## Known risks

- Alpha packages advertise four continuously tested targets; Windows arm64, Linux arm64, and musl are not advertised until protected CI can build and smoke-test them.
- The checksum helper verifies packaged or externally supplied bytes, but no download fallback exists under ADR 0010.
- MCP tool annotations are hints; clients remain responsible for explicit user consent, especially for execution and memory writes.
- The built-in stats method exposes persistent, content-free aggregate context savings grouped by tokenizer and exactness. It never stores prompts, source text, paths, commands, or model responses.
- Managed update activation, rollback, scheduling, and unattended application remain post-v1 work under ADR 0012.
