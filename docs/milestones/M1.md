# M1: Core contracts, routing, and token estimation

Status: Complete  
Completed: 2026-08-07

## Delivered

- validated, Serde-enabled request IDs, protocol versions, token budgets, route requests, route decisions, and token-count identities;
- deterministic `FAST`, `BUILD`, and `DEEP` routing with ordered precedence and stable reason codes;
- request and configured mode overrides without a fabricated confidence value;
- configurable 4K, 16K, and 48K default budgets with per-request budget overrides;
- eight public JSON routing fixtures covering precedence, automatic selection, ambiguity, and budgets;
- `byte_upper_bound_v1`, a deterministic UTF-8 byte-length fallback that always labels results as estimated;
- in-order budget selection that records selected and omitted candidates and never exceeds the effective limit;
- a Criterion microbenchmark for the deep-route hot path.

## Acceptance commands

```text
pnpm check
cargo bench -p token-shrinker-router --bench route
git diff --check
```

The Rust suite contains 12 M1 tests: five shared-contract tests, four routing tests, and three estimator/budget tests. The workspace gate also compiles every benchmark target under strict Clippy warnings.

## Benchmark

On the local Windows development machine, Criterion measured `route_deep_request` at approximately 78–82 ns. This comfortably clears the current 25 ms routing-overhead target, but it is an informational development measurement rather than a portable release baseline.

## Known risks

- UTF-8 byte length is intentionally conservative and may underfill context budgets substantially.
- No exact model tokenizer is registered yet.
- Callers currently normalize goals into operation and scope signals; natural-language signal extraction is not part of M1.
- Generated JSON Schema and checked-in TypeScript protocol types remain future protocol work.
- No persistent cross-machine benchmark baseline is published yet.
