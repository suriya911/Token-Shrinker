# M2: Context, repository, and built-in memory

Status: Complete  
Completed: 2026-08-07

## Delivered

- a shared context-provider contract and normalized repository-file, repository-symbol, and memory candidates;
- validated opaque source IDs, source locations, content hashes, sensitivity labels, and deterministic score breakdowns;
- content-hash deduplication, stable ranking, budget packing, explicit omission reasons, and reproducible bundle hashes;
- content-free context and repository traces containing only counters, identifiers, hashes, and policy outcomes;
- root-confined native repository scanning with ignore rules, generated/vendor defaults, bounded reads, text/path signals, cancellation, and a metadata-aware content cache;
- pre-cache secret-redaction hooks and post-read metadata rechecks that prevent stale content from entering the cache during concurrent changes;
- optional definition-line symbol enrichment that runs only after native text/path discovery and remains retrievable through bounded source references;
- SQLite schema migration, FTS5 with deterministic fallback search, scoped memory CRUD, expiration pruning, deletion, integrity checks, and a bounded `r2d2` pool;
- an end-to-end native baseline that scans the deterministic demo repository and builds an identical budgeted bundle without optional tools.

## Acceptance commands

```text
pnpm check
cargo bench -p token-shrinker-context --bench rank_and_pack
git diff --check
```

Focused tests cover golden ranking and hashing, budget bounds, root escape attempts, symlinks, Unicode and case-insensitive matching, generated files, binaries, oversized files, cancellation, concurrent repository changes, redaction/cache ordering, interrupted SQLite writes, forward migration, retention, FTS fallback, and concurrent pooled writes.

## Benchmark

On the local Windows development machine, Criterion measured deterministic ranking, deduplication, packing, trace construction, and SHA-256 bundle hashing for 100 candidates at approximately 99–104 microseconds. This is development evidence, not a portable release threshold.

## Security boundaries

- Repository paths are canonicalized and checked against the allowed root before reading, hashing, caching, or candidate admission.
- Symlinks are not followed during discovery; direct source retrieval rechecks the canonical target.
- Redaction occurs before content hashing and cache insertion.
- Default traces never contain source or memory content.
- Optional symbol candidates can only be derived from text already admitted by native discovery.

## Known risks

- The current score function intentionally uses a small deterministic signal set; richer diagnostics and pin/recency policy remain future work.
- The conservative byte estimator may leave budget unused until exact tokenizer providers are added.
- Built-in symbol extraction recognizes common definition lines, not full language grammars; graph and tree-sitter integrations remain optional-provider work.
- FTS queries currently use exact phrases, with deterministic substring search as the compatibility fallback.
- Windows symlink coverage is skipped when the local account lacks symlink privileges; CI supplies cross-platform coverage.
