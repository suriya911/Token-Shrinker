# M6 — Optional providers

M6 adds five optional, local-process integrations without changing the built-in M4 path:

| Capability | Adapter | Tested versions | Built-in fallback | Data boundary |
|---|---|---|---|---|
| repository graph context | Graphify | `>=0.9.0, <0.10.0` (live: `0.9.35`) | native repository scan | query and graph path enter the Graphify process |
| context compression | Headroom MCP | `>=0.22.0, <1.0.0` (live: `0.34.0`) | built-in extractive compressor | context enters the Headroom MCP process |
| terminal compression | RTK | `>=0.45.0, <1.0.0` (live: `0.45.0`) | built-in terminal compressor | captured output enters the RTK process |
| memory search | Claude-Mem MCP | `>=13.0.0, <14.0.0` | local SQLite memory | query enters the configured Claude-Mem process |
| memory search | generic MCP | configured semantic-version range | local SQLite memory | query enters the configured MCP process |

External memory adapters are read-only. Explicit `remember` writes continue to use local SQLite unless a future provider contract adds a separately authorized write capability.

## Safety contract

`token-shrinker-provider` is the shared subprocess/MCP boundary. It launches an exact executable and argument vector without a shell, uses separate startup and operation deadlines, bounds stdout/stderr and MCP message sizes, validates semantic versions and response schemas, and opens a 30-second circuit after three consecutive failures.

Unavailable, timed-out, crashed, malformed, oversized, incompatible, and missing-capability providers produce stable warning codes. Optional providers use the built-in result for that request; a provider marked `required` returns the original classified error. Fallback attribution records both the selected built-in provider and the failed preferred provider.

Headroom is a special version-probe case: its package version is read from `headroom --version`, while its MCP handshake is used for protocol and `headroom_compress` capability checks. The MCP server's own runtime version is not mistaken for the Headroom package version.

The default `PublicHandler::new()` enables no optional provider. Its context, compression, and memory behavior therefore remains the deterministic M4 baseline. Public envelopes now contain content-free `providerAttribution`; the existing telemetry provider-event schema stores the corresponding provider, operation, status, duration, and warning code.

## Verification

Default contract tests use a cross-platform fake provider and cover success, absence, timeout, crash, output overflow, malformed data, incompatible versions, missing MCP tools, circuit opening, safe fallback, and required-provider failure. Live tests are ignored by default:

```text
cargo test -p token-shrinker-repo live_graphify_probe -- --ignored
cargo test -p token-shrinker-compress live_headroom_probe -- --ignored
cargo test -p token-shrinker-compress live_rtk_probe -- --ignored
cargo test -p token-shrinker-memory live_claude_mem_probe -- --ignored
```

The Criterion target `provider_contract` measures incremental contract overhead and the comparable reduction/evidence-recall scoring path. Provider quality uses one labeled token counter for raw and optimized counts and explicit relevant-evidence fixture totals.

At completion on Windows:

- Graphify `0.9.35`, Headroom `0.34.0`, and RTK `0.45.0` passed live probes.
- Claude-Mem was not installed and `doctor` correctly reported `provider-unavailable` with SQLite fallback active.
- Rust workspace tests: 94 passed before final documentation-only changes.
- Node workspace tests: 15 passed.

Run `token-shrinker doctor --json` to inspect compatibility, tested ranges, data boundaries, native-transport safety, and active fallback diagnostics without exposing provider output or configuration values.
